# Game shell (formats) and input layer

Game routes only (`GAME_ROUTES` in `form-factor.ts`); instruments are untouched. Both dirs are
extractable: no imports from instruments (only `@/i18n`, `@/settings`, `@/lib/escape-stack`).
Mounted once in `App.tsx`: `<InputRoot/>`, `<GameShellRoot/>` inside `HashRouter`.

## Formats (`src/game-shell`)

- `<html>` on game routes: `data-game`, `data-ff` = phone-portrait | phone-landscape | tablet |
  desktop (by space, not device: short side < 560 → phone; w ≥ 1280 && h ≥ 640 → desktop; else
  tablet), integer `--ui-scale` + `--ui-px` (phone 2, tablet/laptop 3, 1080p 4, 1440p+ 5, capped
  so 160 art px fit the short side). The player's «interface size» is L's `useSettings().uiScale`
  (auto | 1 | 2 | 3); `shell-state.ts` subscribes to it.
- On every route: `data-input` (touch | mouse | keyboard | gamepad — last used) and `data-pad`
  (xbox | ps | nintendo, from the pad id; check xbox FIRST — «Xbox Wireless Controller» also
  matches the PS «wireless controller» pattern).
- Game routes never scroll the document: html/body `overflow: hidden`, `overscroll-behavior:
  none`; `#root` is the scroller. Pull-to-refresh/rubber band are therefore off.
- Telegram: safe areas from `--tg-viewport-(content-)safe-area-inset-*` → `--gs-safe-*`;
  orientation unlocked via `postEvent('web_app_toggle_orientation_lock', {locked:false})` only
  under `isTMA()`; vertical swipe is disabled by App already.
- `<GameScreen>` (top / nav / main / side / bottom / bg) — portrait: one column, nav at the
  bottom; landscape/tablet/desktop: nav = left rail, side = right column, each column scrolls.
  `<GameNav>` cycles with Tab/Shift+Tab and LB/RB. `TipHost` shows `[data-tip]` tooltips for the
  MOUSE only (`data-tip-key` appends the bound key: «Питомцы · P»).

## Input (`src/input`)

- Action bus: handlers are a stack (last registered first); `true` eats the event and
  `preventDefault`s. `InputRoot` is the bottom: back (blur field → `closeTopOverlay()` →
  `navigate(-1)`), pad confirm clicks the focused element, arrows/D-pad/stick move focus.
- Bindings by `KeyboardEvent.code` (layout-independent: WASD works in the Russian layout).
  Storage `input.bindings.v1`; `normalizeBindings` fills new actions with defaults.
- `useGameplayCapture(active)` — while a fight/walk is on: arrows don't move focus, pad B is
  dash (not back), pad Start = Esc (pause via escape-stack). Used by `DungeonRun` and the yard.
- Gamepad: standard mapping, deadzone 0.24 radial, stick-as-dpad at 0.55, repeat 380/110 ms. rAF
  loop runs only while a pad is connected.

## Pitfalls (each cost a debugging round)

- **`useNavigate()` changes identity on every navigation (react-router 6).** An effect depending
  on it reinstalled the gamepad poller per screen; the new poller saw a held B as a fresh press
  → back twice. Keep `navigate` in a ref, effect deps `[]`. The poller is also PRIMED: its first
  step (and the first after `reset()`) only records held buttons.
- **Top layer = INNERMOST fixed, viewport-covering ancestor that has focusables** (or the last
  visible `[data-ui-layer]`). The outermost one was wrong: the dungeon screen is itself fixed
  full-screen, so its pause modal was skipped and the D-pad walked the HUD behind it.
- **Rebinding capture listens in the CAPTURE phase on window and also eats the keyup** of the
  captured key; otherwise Space/Enter reached the focused cell after capture and started it
  again. Pad capture: the button that clicked the cell is seeded as held, not captured.
- First focus skips window close buttons (`*__close` class, `data-focus-last`) — B/Esc closes.
- Stand: Vite does not pick up NEW files in `public/` after start (served index.html as png) —
  restart Vite after merging assets. The prison dock mounts ~2 s after load: wait for
  `.pmx-dock` before pressing hotkeys. Eruda overlays touch-context pages: click via
  `dispatchEvent`.

## Controls tab

`BindingsPanel.tsx` registers itself as `settingsPanels.controls` (L's settings): two keyboard
cells + one gamepad cell per action; Esc cancels, Backspace clears, 10 s timeout;
`assignBinding` SWAPS with the action of the same group that had the key. Strings — i18n area
`input` (7 languages, generated by the S scratch script; edit `ru` first, then all others).
